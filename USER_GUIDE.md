# MetaStore — руководство пользователя

Это руководство объясняет **зачем** нужен MetaStore и **как** им пользоваться без погружения в код. Технические детали реализации см. в [TECHNICAL_ARCHITECTURE.md](TECHNICAL_ARCHITECTURE.md).

---

## 1. Что такое MetaStore

**MetaStore** помогает вести учёт **файлов на ваших компьютерах и дисках**, не копируя сами файлы на центральный сервер. На сервер попадают только **описания**: имя файла, относительный путь внутри выбранной папки, размер, дата изменения (как сообщает система), контрольная сумма (если включена при сканировании), привязка к устройству.

Типичные задачи:

- помнить, **на каком ПК и в какой папке** лежит нужный документ;
- после массового сканирования **разобрать** новые находки: привязать к проекту и тегам;
- искать по каталогу через веб-интерфейс.

**Важно:** если вы ожидаете «облако с файлами», это другая задача — MetaStore **не заменяет** файловое хранилище и **не загружает содержимое** файлов на сервер.

---

## 2. Из чего состоит система

| Часть | Где живёт | Что делает |
|-------|-----------|------------|
| **Сайт (сервер)** | Обычно один общий адрес в браузере | Каталог, проекты, теги, разбор результатов сканирования |
| **Сканер (программа на вашем ПК)** | Папка `metastore-scanner` на компьютере | Обходит указанные каталоги на диске и отправляет метаданные на сервер |

Вам нужны **обе части**: без сканера сервер не узнает о новых файлах на диске; без сервера сканер только накапливает данные локально (или вовсе не синхронизируется).

---

## 3. Работа с сайтом

Откройте в браузере адрес вашего развёрнутого MetaStore (тот, что выдал администратор).

### 3.1 Основные разделы

- **Главная и списки** — обзор разделов каталога.
- **Проекты** — логические группы материалов (например, «Диссертация», «Работа 2025»). Проект можно назначить материалу при разборе очереди скана.
- **Материалы** — записи о файлах и связанных объектах; часть записей может помечаться как ожидающие разбора после сканирования.
- **Теги** — произвольные метки для фильтрации и группировки.
- **Поиск** — зависит от настроек сайта (имена, теги, типы материалов).

Интерфейс выполнен в виде веб-страниц с формами (Bootstrap). Точные названия пунктов меню могут слегка отличаться в вашей сборке, но смысл разделов сохраняется.

### 3.2 Разбор скана («очередь импорта»)

После успешной отправки данных со сканера на сервер новые файлы часто попадают в специальную очередь — раздел вроде **«Разбор скана»** (в адресе может быть путь `/scan-inbox/`).

Там вы видите записи, которые **ещё не привязаны** к вашим правилам каталогизации. Для выбранных строк обычно можно:

- указать **проект** и **теги** и сохранить — запись становится полноценной частью каталога;
- **удалить** запись из каталога, если файл попал по ошибке;
- **убрать из очереди без удаления** («игнор») — материал остаётся в базе, но больше не мешает в этой очереди (удобно для служебных или уже учтённых файлов).

Если вы не видите раздела «Разбор скана», уточните у администратора ссылку или права доступа.

### 3.3 Как сканировать (справка на сайте)

На многих установках есть страница **«Как сканировать»** с готовыми командами для копирования в PowerShell или командную строку Windows. Используйте её как быстрый шпаргалку рядом с окном терминала.

## 4. Установка сканера на компьютер

### 4.1 Что понадобится

- **Python** (версию уточняет администратор; обычно 3.10+).
- Папка с программой **`metastore-scanner`** из репозитория или готового архива.
- Доступ по сети к адресу сервера MetaStore (URL вида `http://...` или `https://...`).

### 4.2 Установка зависимостей и пакета

В командной строке перейдите в каталог `metastore-scanner` и выполните установку зависимостей и самого пакета в режиме разработки (пример):

```powershell
cd путь\к\metastore-scanner
pip install -r requirements.txt
pip install -e .
```

После этого команда **`metastore-scanner`** может быть доступна глобально; если нет — всегда можно запускать через **`py -m scanner.cli`** из этой же папки (как в справке на сайте).

### 4.3 Файл настроек `scanner.yaml`

В каталоге сканера (обычно там, откуда вы запускаете команды) создайте файл **`scanner.yaml`**. Удобно скопировать пример:

```powershell
copy scanner.example.yaml scanner.yaml
```

Откройте `scanner.yaml` в текстовом редакторе и обязательно задайте:

- **`server_url`** — адрес вашего MetaStore, например `http://192.168.1.10:8000` (точное значение даст администратор);
- **`scan_paths`** — список папок на вашем диске для регулярного сканирования (можно несколько).

Пример минимального содержимого:

```yaml
server_url: "http://ВАШ-СЕРВЕР:8000"
scan_paths:
  - "D:\\Документы"
  - "C:\\Users\\ВашеИмя\\Downloads"
```

Пути в Windows в YAML удобно указывать с **двойным обратным слэшем** `\\` или в **кавычках** с обычными `\`, главное — чтобы строка была валидной для YAML.

**PyYAML:** для чтения YAML нужен пакет PyYAML; если при первом запуске появится ошибка про YAML, выполните:

```powershell
pip install PyYAML
```

## 5. Основные команды сканера

Все команды выполняются в **PowerShell** или **cmd** из каталога установки сканера (или с учётом того, что `scanner.yaml` лежит в **текущей папке** процесса).

### 5.1 Проверить «отпечаток» компьютера

```powershell
py -m scanner.cli device-info
```

или

```powershell
metastore-scanner device-info
```

Вывод показывает имя машины и идентификатор — так сервер отличает ваш ПК от других.

### 5.2 Полное сканирование настроенных путей

Если в `scanner.yaml` уже указаны `scan_paths`:

```powershell
py -m scanner.cli scan
```

При первом успешном контакте с сервером устройство зарегистрируется, токен сохранится локально (в файле базы **`scanner.db`** рядом с рабочей папкой). Дальнейшие запуски используют сохранённый токен.

### 5.3 Сканировать одну папку (разово)

```powershell
py -m scanner.cli scan --path "D:\МоиФайлы\Проект"
```

Подставьте свой путь в кавычках.

### 5.4 Только файлы определённых типов (расширений)

Чтобы не перечислять маски вручную, можно указать расширения:

```powershell
py -m scanner.cli scan --path "D:\Документы" --ext pdf --ext docx
```

Допустимо писать `pdf` или `.pdf`. Несколько типов — несколько раз **`--ext`** или перечисление в одном аргументе через запятую (в зависимости от версии; надёжнее повторять `--ext`).

В конфиге YAML это же задаётся списком **`find_extensions`**.

**Важно:** режим «только такие расширения» работает в связке с тем, как настроен поиск — см. следующий раздел.

### 5.5 Поиск «только уже известные из базы сканера» vs «всё подходящее на диске»

У сканера есть локальная база **`scanner.db`**, где запоминаются уже виденные пути.

- Если вы указали маски (**`--find`**, **`--ext`**) **без** специального флага полного поиска, по умолчанию обрабатываются **в основном те файлы, которые уже есть в локальной базе** под этим корнем (ускорение и меньше шума).
- Если нужно **найти все PDF (и т.п.) под папкой заново**, используйте флаг **`--find-discover-all`** (в YAML аналог — **`find_discover_on_disk: true`**).

Пример:

```powershell
py -m scanner.cli scan --path "D:\Архив" --ext pdf --find-discover-all
```

Смысл в том, чтобы при необходимости **перечитать весь диск** под выбранным корнем, а не только старые записи кэша.

### 5.6 Другие полезные флаги (кратко)

- **`--dry-run`** — показать, что бы отправилось, без записи на сервер (для проверки).
- **`--quiet`** — меньше сообщений в консоль (удобно в скриптах).
- **`--full-rescan`** — пересчитать контрольные суммы для всех файлов (дольше).
- **`--modified-after`** / **`--modified-before`** — на сервер уйдут только файлы, у которых дата изменения попадает в указанный интервал (обход папок при этом всё равно выполняется).

Полный список:

```powershell
py -m scanner.cli scan --help
```

### 5.7 Если сервер был недоступен

Сканер может сохранить результаты в **очередь отправки**. Когда сеть восстановится:

```powershell
py -m scanner.cli sync
```

Команда попытается отправить накопленное.

### 5.8 Проверить связь с сервером

```powershell
py -m scanner.cli status
```

### 5.9 Сброс локального кэша сканера

Удаляет локальную базу учёта сканера (не файлы на диске!). Используйте только если понимаете последствия — например, перед чистым пересчётом:

```powershell
py -m scanner.cli reset-cache
```

## 6. Типичный рабочий процесс «от диска до каталога»

1. Администратор поднимает сервер MetaStore и сообщает вам **URL**.
2. Вы ставите **сканер**, создаёте **`scanner.yaml`** с этим URL и своими папками.
3. Запускаете **`scan`** (целиком или для одной папки).
4. Дожидаетесь сообщения об успешной отправке (или выполняете **`sync`** позже).
5. Открываете сайт → раздел **«Разбор скана»** → назначаете **проект** и **теги** нужным позициям.
6. Дальше ищете материалы через обычный **поиск** и списки.

## 7. Частые вопросы и проблемы

**Почему на сервере нет моих файлов?**  
Проверьте: выполнен ли **`scan`** без ошибок, есть ли **`server_url`** в `scanner.yaml`, не блокирует ли файрвол доступ к порту сервера. Попробуйте **`status`**.

**Почему сканер «видит» не все новые файлы при фильтре по расширению?**  
Возможно, включён режим без полного поиска по диску — добавьте **`--find-discover-all`** или сначала сделайте полный скан без фильтра, чтобы локальный кэш заполнился.

**Где хранится токен?**  
В локальной SQLite-базе сканера (**`scanner.db`**), не выкладывайте её в публичные места.

**Можно ли сканировать сетевой диск?**  
Если ОС представляет его как обычную папку с буквой диска или UNC-путём — обычно да; права на чтение должны быть у пользователя, запускающего сканер.

**Удалили файл на диске — что на сервере?**  
При следующем скане сканер может сообщить об исчезнувших путях; в каталоге у соответствующих записей обновится статус наличия (подробности зависят от версии и настроек). Уточняйте у администратора политику «архив vs удаление».
